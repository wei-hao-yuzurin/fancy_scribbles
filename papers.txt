Отчёт (текст)

Каждая работа начинается с общего плана работы с материалом, после чего производится поочередное выполнение пунктов плана. Операционной системой для разработки выбирается Ubuntu версии 24.04.03 LTS. 
Это связано с непревзойдённой лёгкостью, которая сопровождает установку и координирование программного обеспечения в свяси с тем что Linux системы являются стандартом при разработке. В качестве редактора 
кода используется VS Code и bash терминал для исполнения написанного кода интерпретатором. Версия Python - 3.12.3, баланс между современными функциями языка и стабильностью системы, кроме того гарантриуется
наличие всех требующихся библиотек.

Общий план: придумать содержание логов, написать генератор логов выбранного формата, запланировать потенциальные сценарии чтения и обработки логов в реальной жизни и написать код для эффективной работы скрипта
(в том числе, оптимизация вложенных циклов). После этого начинается второй пункт задания, сервис по созданию и хранения заметок с стандартизированным пользовательским интерфейсом (далее API). После завершения второго пунка,
необходимо выбрать базу данных с учётом того, что она будет запускаться на хостинге, т.е. оптимального размера на диске во избежание переполнения памяти, и дополнить кодовую базу сервиса методами базы данных, 
позволяя пользователям сохранять свои записи между сессиями. Последний шаг - определение оптимального хостинга и деплой сервиса заранее подготовленными скриптами для минимизации дальнейшей ручной работы.

1) Обработка логов с оптимизацией
В связи с прохождением курса по питону на платформе Stepik и School21, было принято решение сразу приступить к написанию кода. В моей интерпретации первого пункта задачи, студенту в свободной форме предлагается определить 
форму логов (записей работы программ, генерируемых автоматически) и составить в голове схему возможных запросов, которые мог бы иметь пользователь, когда сталкивается с неправильной работой программы.
Состав логов выбран минимальным: временная отметка, ID пользователя, при котором был составлен лог, HTTP код процесса (хотя в энтерпрайз разработке могут применяться собственные, в том числе текстовые варианты, я решил
использовать уже готовые решения) и комментарий. HTTP коды выбраны в том числе потому, что графическая часть сервиса реализуется в формате вебсайта, генерирующего содержание контейнера в виде страницы, потому HTTP 
является естественным вариантом. 
Разобравшись с форматом, нужно задуматься над тем, чтобы получить достаточное количество таких логов. С помощью небольшого Python скрипта создаём себе произвольное количество строк логов, формат выбираем JSON 
(JSON - JavaScript Object Notation) для удобной обработки с помощью соответсвующей библиотеки. Становится ясна проблема - число логов (чистого текста) может достигать внушительных размеров, и поиск необходимых может 
занять длительное время при наивном переборе с помощью циклов. Первая часть решения проблемы - применение JSON, что лишает нас необходимости писать на питоне хотя бы обработку текстового файла, позволяя быстро парсить 
по блокам (библиотека написана на CPython, достигая значительного ускорения).
